# Agent operating rules

## Product
Build Material 3 tools that improve actual UI artifacts. An MCP docs wrapper alone is insufficient. See docs/plans/implementation.md for authoritative scope and interfaces.

## Non-negotiables
- Ordinary MCP handlers are local deterministic computation: no model calls, shell, network, browser or arbitrary file writes.
- Refresh and browser evaluation are explicit commands outside tool runtime.
- Keep retrieved official excerpts, authored guidance, and computed results distinguishable. Cite actual provenance; never fabricate source content.
- Validate and bound every input. Treat goals, fonts, URLs, flow labels and generated test strings as untrusted data. No direct interpolation into executable source.
- Static code findings are heuristic, not accessibility certification. Report uncertainty and provide browser/manual follow-ups.
- Native default focus indicators are valid; merely finding :focus-visible does not demonstrate an indicator. Noninteractive elements and disabled native controls have different state requirements.
- Do not claim a WCAG 44px AA requirement. Distinguish AA minimum with exceptions from enhanced/project comfort thresholds and platform-specific Material guidance.
- Tests generated by our own tool are not an independent oracle. Maintain independent bad/clean fixtures and held-out user goals.
- No claimed UX/agent uplift without repeated controlled evaluation; human usability and assistive-tech tests stay explicit.

## Workflow
1. Read plan and affected code.
2. Add failing regression/spec test.
3. Implement smallest useful behavior and run targeted tests.
4. Run independent spec review, fix, then code quality/security review.
5. Run npm test, npm run build, npm run smoke, npm run evals, npm run evals:ui and Docker smoke before declaring release readiness. Record blockers/unrun gates honestly.
6. Never commit node_modules, downloaded doc cache, private browser data, raw agent transcripts or screenshot/test-report artifacts. Keep reproducible fixtures and summarized verification only.

## Supply chain
Exact-pinned direct versions, committed lockfile, at least seven-day package release age, no install lifecycle scripts. No global installations or new cloud services. Verify package registry provenance and keep audit results visible. Do not execute downloaded source as scripts during documentation import.

## Scope for this session
Repository is private under Oni1xyz. No npm publication, public deployment, or modification to global Hermes config without a separate authorized step. No secrets required for running this server. If future integration needs credentials, use Agent Vault rather than plaintext files or chat.
